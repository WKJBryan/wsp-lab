# wsp-lab

A complete replication, stress-test, and extension of **weight-space programming** — the claim, from the MIT CSAIL post [*Sparks of Weight-Space Programming*](https://rikiyat.github.io/blog/weight-space-programming) (Nov 2026), that an agentic LLM given a neural network's raw weights can diagnose and repair it through direct weight edits alone: no gradient updates, no fine-tuning, just arithmetic on parameter tensors.

**All model evaluation ran locally on one RTX 5090. The editor models ran through the host's configured providers; some sessions used paid API paths (ISSUES #25). Every final is reproducible from this repo; the practice passes of phases 4 to 10 are not, because their generations were not saved.**

The original used one editor (OpenAI gpt-6-astra, hinted, 50 evaluation passes) and released [full logs](https://github.com/RikiyaT/lm_understand-logs) — but no cross-editor replication existed, no random-edit control had been run, and (as we verified from their logs) the headline repair was **hinted** in the initial task instructions, with the no-hint condition never tested at full budget. This repo adds the cross-editor replications (phase 4) and the random-edit control, and in phase 10 offered a blind editor all 50 passes. It leaves the hint question open: the experiment that would isolate the hint has not been run (finding 3).

## TL;DR — the final scoreboard

Target: Qwen3.5-0.8B, whose "thinking" degenerates into infinite `Wait, no.` loops (stock scores **8.4%** on MATH-500; 91% of generations hit the token cap). All arms share the same 500 problems, engine (vLLM) and scorer (`phase3c/rescore.py`), with blind editors unless noted — except the starred phase-3a row, which carries its own caveat.

Scores re-scored 2026-11-24 with the final answer checker (ISSUES #19, corrected twice that day). Calibrated 2026-11-24/25 on the original authors' protocol and grader: our stack reads 7.8% for the unedited model against 7.2% outside (openwsp), 51.0% for the published edit against 50.6% (openwsp) and 48.1% (the original authors), and 46.2% for the unedited model with thinking switched off against 46.8% — the harness reproduces the outside numbers. Scores in this repository are read by our own matcher, which is stricter than math-verify: on the calibration runs' boxed answers it reads 4.4 points lower for the published edit and 5.0 points lower for the unedited model with thinking switched off (0.4 for stock), and never higher; read by the repository's usual rule, the same published-edit run gives 49.0% (ISSUES #30). So our levels sit a few points below an outside-scale reading of the same answers; every comparison inside the repository uses the same matcher.

## What we learned — results and thoughts

1. **The core claim is real and robust.** Ten of fourteen blind editor sessions shipped a repair edit, and all ten used the same weight row (the stop-thinking token's embedding row), scaled about ×1.5. They came from four blind editor models — GLM-5.3, GLM-5.3-Flash, mimo-v2.6-flash and mimo-v2.6-pro — working with no hints and no training. When independent surgeons converge on one knob out of 873 million, that's the signature of a real, fundamental target. **Restated by phase 8:** what they converged on is a decoding fix — the same score is reachable with the weights untouched, by adding a constant to the stop-thinking token's score — and none of the blind edits beats the unedited model with thinking switched off (41.4% against a best blind edit of 36.2%). The original authors' published edit does beat it: 48.6% against 41.4%, a gap of 7.2 points under our checker (95% interval 2.8 to 11.8), though not distinguishable under the second grader (math-verify).
2. **But it's repair, not enhancement.** The edits unstick a broken "stop thinking" switch; they don't add intelligence. A healthy stock model with thinking switched off scores 41.4%; the best blind repair reaches 36.2%, 5.2 points lower. Nobody — including the original — has shown an ability *gain* from weight surgery here. (One number now points the other way and is left open: under our checker the original's published edit scores 7.2 points above that thinking-off baseline — finding 1 — though the second grader cannot tell the two apart.)
3. **The gap to the original is not a measurement of the hint.** The blind editors that converged on the stop-token row score 31.6% to 36.2%, and the original authors' hinted editor 48.6% on our stack (48.1% on theirs), but the two experiments differ in at least four ways at once, so the gap cannot be attributed to any one of them (ISSUES #23). Their task instructions named the failure (the model repeats itself in its thinking). Their task instructions and harness forbade the quick fix — edits to the embedding or output layer, skipping or closing thinking early, and multiplying a whole tensor by a constant — and the edit every blind editor here converged on is a rescaling of rows in that embedding. Their editor practised on 7,469 GSM8K, 7,275 MATH and 714 AIME problems, up to 512 per pass at the full 32,768-token cap, over 50 passes; ours practised on 64 GSM8K problems per pass at an 8,192-token cap. And their editor was a frontier model (gpt-6-astra); ours were small local-tier models. What is measured is a quick fix against a deeper edit under different rules, practice data and editor models. The experiment that would isolate the hint — a blind editor under the original rules, with in-distribution practice — has not been run. More budget alone did not close the gap: offered 50 passes, a blind editor used 6 and scored 36.0% — 4.4 points above its 6-pass GLM-Flash run (95% interval 0.2 to 8.6, at the edge of what 500 problems can tell apart; +3.6, interval −0.4 to 7.8, p = 0.11, under the checker's other line rules — ISSUES #31), indistinguishable from the MiMo-pro edit, and 4.4 of the 17.0 points closer to the published edit — 26% of the way, where a third would be 5.7 (phase 10).
4. **Committees did not beat single editors — in five single sessions.** None of the five phase-9 committees that shipped an edit (of eight conditions run) beat the single editor it is compared with. Three were far worse: the GLM-5.3-Flash team 15.2% against 31.6% (−16.4), the interleaved pair 11.8% against 31.6% (−19.8), the mimo-flash team 8.2% against 36.2% (−28.0). The GLM-5.3 team was not distinguishable from its single editor (30.2% against 29.6%), and the mixed team scored 29.6%, 6.6 points below the best single editor (36.2%; 95% interval −10.6 to −2.8). Each committee is one session, one seed, so this is a pattern noticed after the results. The committees did produce the phase's most sophisticated *methods* (untied heads, escalation gates, a depth-gated additive mechanism) and its most cautious *doses*; that they under-dose, and that gentle doses die on hard problems, is a reading offered after the results. Red-teams were right about every risk they measured — and wrong about which risk mattered.
5. **Session format beats model tier — in these sessions.** mimo tiers could not hold a whole multi-role session (empty reports, leaked reasoning) yet produced the best red-team work of the project when given one focused seat. The harness around a model matters as much as the model.
6. **The loudest scientific killer was measurement, not models.** Our biggest wrong conclusions came from our own rig: a decoding regime in which nothing could succeed, justified by a model-card sentence that is not on the card (ISSUES #8, #26), a scorer that silently failed on Windows, an `ast.parse` check that doesn't catch repeated keywords. (The last was caught by the *editor models*, twice.) The latest, found 2026-11-24, was our own answer checker, which had been misreading correct answers written in a sentence — the published edit reads 48.6% under the final checker against the 39.4% first reported, and the best blind edit 36.2% against 27.8% (ISSUES #19). When results look wrong, suspect the ruler first — the user's instinct on this was the project's most valuable instrument.
7. **Symptoms are self-hinting; silence is the frontier.** Blind discovery worked because loops shout in the outputs. The original's own weights-only sycophancy hunt failed 4× — because flattery leaves no visible trace. Understanding is only needed where watching isn't enough.

## Corrections of 2026-11-23/24

A fresh-eyes audit on 2026-11-23 found several headline claims wrong or unsupported. What changed (ISSUES #19–#31):

- **Answer checker (ISSUES #19, corrected twice).** `phase3c/rescore.py` discarded correct answers written in a sentence: it removed the final period and then the closing `$` of a math span (first correction). That still misread a whole family of correct answers: `The value of $x$ is **83**` was scored as "x", a unit was glued to its value (`$\frac{16}{27}$ gallons`), and a money answer written `$\$10$` could not match a gold answer of "10" (second correction, the same day, after a test author found the first case). Measured answer by answer on the 20,218 saved answers of phases 3c, 8, 11 and 5: against the rule as first committed, the final checker turns 1,125 answers from wrong to right and 11 from right to wrong; against the first re-score, 570 from wrong to right and 1 from right to wrong; against the first correction as last refined, 520 right and none wrong. Seven of the 11 are misreads that remain in the final checker (it is frozen here; the list is in ISSUES #19), so no quoted score is exact to the last answer — each is one answer of a 500-problem run, 0.2 points. Covered by 46 unit tests, and every saved run re-scored. As first reported → under the final checker: stock 6.0% → 8.4%, published edit 39.4% → 48.6%, best blind edit 27.8% → 36.2%. The practice passes of phases 4 to 10 cannot be re-scored, because their generations were not saved.
- **Verdict words that changed with the second correction (ISSUES #29).** Three registered predictions now read differently. Phase 8's B-2 (the blind edit, with thinking switched off, lands within 4 points of the unedited model with thinking switched off) goes from miss to hit, exactly on its bar. (Under the checker's other line rules it reads −4.2 and would be INCONCLUSIVE; ISSUES #31.) Phase 7's V3 (the half-dose stack lands between 38% and 44%, at or above the full-dose one) goes from hit to miss on both counts: 44.8% is just above the band, and the clean rerun of the full-dose model scores 46.2%. Phase 10's band prediction (the 50-pass edit lands between 28% and 34%) goes from hit to miss: 36.0% is above the band. Two exploratory statements change too: the unedited model with thinking switched off is no longer as good as the published edit (41.4% against 48.6%, 7.2 points behind, 95% interval 2.8 to 11.8 under our checker; not distinguishable under math-verify), and the random control is no longer stock-like (3.8% against stock's 8.4%, 4.6 points below, 95% interval 2.4 to 6.8) — the conclusion it supports stands, that a random change of the same size on the same rows does not help. A third checker limitation was put on record on 2026-11-25 (ISSUES #31) — which line of an unboxed answer is read; it moves no large conclusion, but phase 10's "+4.4 at the edge" becomes +3.6 with an interval that includes zero.
- **Void run (ISSUES #20).** The phase-7 full-dose stacked final (4.4% as first reported, 6.4% under the final checker — neither is a measurement) was reported as the model falling apart. It is a corrupted run: 460 of the 500 generations (92.0%) end in fragments of non-Latin script, and whether a generation was right depends on the request's position in the batch (the first half of the requests scored 12.0%, the second half 0.8%; every one of the 32 right answers is among the first 266 requests; exact test p = 1.1e-7). It is void. The clean rerun of 2026-11-24 scores 46.2% (231 of 500) and passes both checks: the collapse was the corrupted run, not the model.
- **Reversed finding (ISSUES #24).** Phase-7 finding 2 said the original's 64 edited columns were not weight-aligned. They are the most weight-aligned ones; the earlier reading had compared the alignment ranking against the edited columns sorted by index.
- **Withdrawn verdict (ISSUES #21).** Phase 12's "COMPLETE, verdict CORRESPONDENCE 2/3" is withdrawn: neither pass is informative, the verdict is NOT ESTABLISHED, and phase 13 is not armed. The same issue records that the three registered tests had been replaced 8.4 hours before the run without a note.
- **Restated phase 11 (ISSUES #22).** The full Gemma model scores 76.4% (58.4% as first reported). The "0 of 21 arithmetic facts" test could not score 20 of its 21 answers and is withdrawn, as is "knowledge deleted". The wound switches expert selection off as well as removing experts, and no matched control was completed.
- **Selection switched back on (phase 11, 2026-11-24).** The Gemma wound keeps 8 of each layer's 128 experts and still activates 8 per token, so choosing between experts was switched off along with the removal. In a copy of the wound with that choice restored (each token picks its one best kept expert; weights unchanged), the 64-problem practice pass still scores 0 of 64 right — the same as the wound as built, rerun in the same session — and 59 of 64 generations hit the token cap against 64 of 64. Removing the experts is by itself enough to destroy performance on this set; whether the switched-off choice costs anything on top cannot be seen at this floor. The full model scores 47 of 64 (73.4%) on the same problems. The phase-11 verdict stays NULL.
- **Report counts and verdict words (ISSUES #23, #25, #26, #27).** "10 of 10 blind sessions" is 10 of 14; "Five different editor models" is four blind editor models plus the original authors' hinted one; "0 of 7 committees" is none of the five that shipped an edit, out of eight conditions; "No paid APIs" was wrong; "the hint is worth ~12 points" is not a measurement; a model-card sentence quoted in ISSUES #8 is not on the card; two phase-9 verdict statements (condition 6's label and condition 7's "confirmed") were outside the registered rule.
- **Phase-14 evaluation tool (ISSUES #28).** The tool that scores a phase-14 editor pass had never been run: as committed it had a syntax error on the line that prints its result, and it looked for the base model's fingerprint in the wrong folder; a pass that failed a validity check was not refunded. Found by a dry run with no GPU against a fake engine, before the editor session. Fixed, and hardened after an independent review of its failure paths (the pass is charged only once the tool holds the GPU lock; an interrupted pass is refunded; each attempt keeps its own texts; the candidate's fingerprint is checked again under the lock and covers every file of its folder); `phase14/test_eval_pass.py` (23 tests) runs the real tool end to end against a fake engine, and `test_parse_all.py` parses every Python file of the repository.
- **Calibration (2026-11-24/25).** Under the original authors' protocol and grader our stack reproduces the outside numbers (7.8 / 51.0 / 46.2 against 7.2 / 50.6 / 46.8). Under that protocol the published edit also beats the unedited model with thinking switched off under both graders (+5.4 and +4.8 points; 95% intervals 1.0 to 9.6 and 0.4 to 9.2). And the calibration exposed one more property of our ruler: the matcher is stricter than math-verify by 4 to 5 points on the same boxed answers, mostly because gold answers are written in LaTeX shorthand it does not expand (ISSUES #30).

## Integrity practices

- **Pre-registration everywhere:** every phase's thresholds, budgets, and controls committed *before* the run (the git history shows the ordering; it was rewritten on 2026-11-23 to remove personal identifiers, so every commit ID changed); deviations logged in [ISSUES.md](ISSUES.md) with reasons.
- **Harness-enforced passes:** the counter file enforces harness passes and refuses one without a logged hypothesis, but it does not gate an editor's own evaluation scripts (ISSUES #12, #25).
- **Runs are checked before they count:** the three main runners take a shared GPU lock before the engine starts, switch prefix caching off, refuse to overwrite a result file, and write the generations before the result. Every finished run is then checked for two signatures of a corrupted run (`phase3c/runcheck.py`), and the check is recorded inside the result file; a failed check exits with status 2 and keeps the files as evidence (ISSUES #20). Every re-scored file records which checker version produced it.
- **Controls the original skipped:** matched-norm random edits (3.8% — it's the edit's *content*, not its size), untouched baselines, retrain ceilings.
- **Full audit trail:** every editor session's ledger and probe scripts are committed, and so are the generations of the finals (gzipped, for re-scoring without a GPU) and of the phase-11 practice passes; the practice-pass generations of phases 4 to 10 were not saved.
- **Failures stay in the record:** wrong turns, void runs, and our own bugs are documented, not buried — see [CHANGELOG.md](CHANGELOG.md) and [ISSUES.md](ISSUES.md) (#4, #8–#31).

## Reproduce

```bash
uv sync                  # torch cu128 (Blackwell) + gymnasium, locked
uv run python phase1/train.py 20      # small-network repair target
uv run python phase1/evaluate.py phase1/ckpt/seed0.pt 64
```

Phases 3+ additionally need WSL2 + vLLM + CUDA toolkit (see `phase3c/results.md` for the full recipe: vLLM 0.33, CUDA 12.8 toolkit, ninja; models ~1.6 GB each). Re-score any committed run without a GPU — the re-scorers read the gzipped generations directly, so no gunzip is needed — and run the unit tests of the answer checker and of the run-validity checks, which need no GPU either:

```bash
uv run python phase3c/rescore.py p4_glmflash     # <run> [<run> ...]; writes <run>_rescored.json
uv run python phase5/rescore_finals.py           # the two phase-5 finals; writes <final>_rescored.json
uv run python phase8/rescore_arms.py             # the phase-8 arms, re-scored in place
uv run python phase11/rescore.py                 # the phase-11 runs, re-scored in place
uv run python -m unittest phase3c/test_rescore.py phase3c/test_runcheck.py   # the checker's 46 tests and the 57 run-validity tests
uv run python -m unittest test_parse_all.py                                 # every Python file of the repository parses
```

(The phase-14 tools have their own suites, which need WSL: 36 tests for the edit checker and 23 for the evaluation tool.)
